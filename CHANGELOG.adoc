= Changelog

This project follows link:https://keepachangelog.com/en/1.1.0/[Keep a Changelog] and uses link:https://semver.org/spec/v2.0.0.html[Semantic Versioning].

== Unreleased

=== Added

* Network activity is logged even for `--no-firewall` sessions by keeping permissive firewall/DNS/proxy logging hooks installed.

=== Changed

* Project `.clamp/clamp.Dockerfile` files now contain only project-specific instructions; Clamp adds the standard image header dynamically at build time. Legacy complete project Dockerfiles remain supported.
* Network allowlists now use explicit `host:port` entries, exact host matching, and resolved IP+port firewall entries.
* Separate startup scripts from command shims: startup scripts now install under `/opt/clamp/startup/`, while command shims such as `xdg-open` stay in `/usr/local/bin/`.

=== Fixed

* Include `libatomic1` in the base image so mise-installed Node.js versions that require `libatomic.so.1` can start, including Node.js 26.12.1 on ARM64.
* Project image builds use a generated Dockerfile-specific ignore file, including only `.clamp/**` and paths declared in `.clamp/clamp.Dockerfile.dockerignore`, instead of depending on the project's root `.dockerignore`.
* Shutdown network summaries now use the session log from the Clamp run that just exited instead of guessing the most recent log.
* Firewall startup on lightweight guest kernels by falling back from `iptables-nft` to `iptables-legacy` when required.

== 0.2.0 - 2026-08-17

=== Added

* Apple `container` CLI support through the new `--runtime docker|container` option; Docker remains the default.
* Configurable DNS for Apple container builds and sessions through `CLAMP_CONTAINER_DNS`.

=== Fixed

* Writable named-volume ownership when Apple `container` creates volumes owned by root.

== 0.1.0 - 2026-08-17

=== Added

* Containerized harnesses for Claude Code, OpenCode, and Pi.
* Per-project Docker images and configurable `.clamp/clamp.Dockerfile` files.
* Global or per-project authentication volumes.
* Allowlisted network access through local DNS and HTTP proxies.
* Network session logging and shutdown summaries.
* Non-root agent execution with restricted privilege escalation.
* Project-selectable allowed-domain files and bundled Claude workflows.
